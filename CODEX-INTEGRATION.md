# InkMap: файл проекта и Codex

## Загрузка доски

Нажмите «Загрузить из проекта», выберите папку непосредственно или через найденный чат, затем «Загрузить доску». Программа читает `.inkmap/project.json`. Если файла ещё нет, создаёт его по исходникам. Запуск Codex и захват чата для этой операции не нужны: ошибка `already has an active writer` больше не мешает загрузке.

Первичная карта содержит корень проекта, группы файлов и модули с именами классов/функций, импортами и TODO. Это статическая структура, а не подтверждение выполнения программы или тестов. Максимум 40 узлов; полный список исходников и их хэши хранится в `source.files`.

По умолчанию загрузка заменяет текущую доску, включая рисунки. Чтобы объединить проекты, выберите «Добавить к текущей карте»: в этом режиме повторная загрузка синхронизирует узлы по стабильным ключам без дублей, сохраняет ручные заметки, размещение, цвета, размеры и вложения. Неизменённые устаревшие импортированные узлы удаляются; изменённые пользователем или связанные вручную узлы сохраняются. Опция «Обновить файл карты по текущим исходникам» пересобирает файл. Замена и добавление отменяются одним Undo. Кнопка «Новая карта» очищает все объекты доски и также поддерживает Undo/Redo.

## Обновление перед сохранением в GitHub

Опция «Обновлять карту перед commit и проверять перед push» устанавливает локальные Git-хуки в уже существующий репозиторий:

- `pre-commit` обновляет файл по staged-снимку и добавляет `.inkmap/project.json` в индекс. Неподготовленные изменения не попадают в карту коммита.
- `pre-push` проверяет карту каждого отправляемого tip, включая ветки и теги. Если карта отсутствует или устарела, push останавливается; карта должна быть обновлена следующим разрешённым пользователем коммитом.

Существующие чужие хуки и `core.hooksPath` не заменяются. В текущей папке IdeaMap пока нет Git-репозитория: файл работает уже сейчас, хуки можно включить после создания репозитория. Git не инициализируется автоматически, commit/push приложение не выполняет. Локальные хуки не охватывают загрузку файлов через сайт GitHub и команды с отключением hooks.

Ручные команды из корня проекта:

```powershell
python project_map.py --install-hooks
python project_map.py --mode index
python project_map.py --mode head --check
```

В другом проекте подключение через InkMap копирует стандартный экспортёр в `.inkmap/sync_project.py` и создаёт `.inkmap/hooks/`. Нужен Python. После клонирования подключите hooks заново: `python .inkmap/sync_project.py --install-hooks`. Абсолютные пути в файл карты не записываются.

## Смысловые пояснения

Codex или пользователь могут дополнить `annotations` в project.json:

```json
"annotations": {
  "file:server.py": {"note":"HTTP API приложения; следующий шаг — добавить отдельные карты проектов.", "status":"todo", "stage":"Планирование"}
}
```

Аннотации сохраняются при пересборке и учитываются в проверке актуальности. Для первой карты достаточно автоматической генерации. `AGENTS.md` требует обновлять пояснения и файл карты перед запрошенными пользователем commit/push.

## Отправка идеи

Выберите объект на доске → «Отправить идею» → конкретный чат или новый чат. Передаются текст заметок, статусы, этапы, теги, связи и URL/пути вложений. Бинарные медиа не передаются. Чат запоминается. Отправка продолжает использовать app-server и требует свободного чата; сообщение о занятом writer теперь объясняет проблему. Самостоятельного форка или дублирующего чата при ошибке не создаётся.

MCP `inkmap` зарегистрирован с разрешения пользователя. `read_board` читает сохранённую доску; `propose_map` публикует предложения в окно InkMap. Сервер должен работать на http://127.0.0.1:8000. На новой машине настройте пути MCP заново. Не переносите авторизацию Codex в архив проекта.

## Проверки и файлы

`python tests/project_map_test.py` — файл карты, исключения, аннотации, staged-снимок, реальное выполнение pre-commit hook во временном репозитории, сохранение чужих hooks; проверка исходящих refs и устаревшей карты для pre-push с тестовым транспортом. Commit и push не выполняются.

`node tests/project-sync.mjs` — синхронизация без дублей, ручные изменения, вложения и позиции.

`node tests/project-file.cjs` — реальное чтение файла через API в Edge при занятом чате, без запроса модели; Undo/Redo и сохранение. Требует сервер на порту 8001 и Playwright/Edge. Карта пользователя подменена тестовой картой в памяти.

`node tests/codex.cjs` — отправка идеи с тестовым транспортом и загрузка файла.

Созданы: `project_map.py`, `.inkmap/project.json`, `AGENTS.md`, `tests/project_map_test.py`, `tests/project-sync.mjs`, `tests/project-file.cjs`. Изменены: `codex_api.py`, `web/proposals.js`, `web/codex.js`, `web/app.js`, `web/index.html`, `web/style.css`, `tests/codex.cjs`, README и эта инструкция.

Официальная документация интеграции: [app-server](https://developers.openai.com/codex/app-server), [MCP](https://developers.openai.com/codex/mcp).
