# Работа с InkMap

Отвечай и составляй рабочие отчёты на русском языке. Перед изменением кода изучай существующую архитектуру и authoritative implementation. Не делай unrelated refactor и не создавай дублирующие системы. Соблюдай принцип: 1 класс = 1 файл = 1 ответственность.

Не выполняй destructive Git operations, git commit или git push без прямого указания пользователя. Не заявляй о runtime/visual PASS без соответствующей реальной проверки.

## Карта проекта перед сохранением в Git

Источником доски проекта служит `.inkmap/project.json`. Экспортёр `project_map.py` читает исходники без их запуска. Смысловые пояснения и планы хранятся в `annotations` по ключам узлов и сохраняются при автоматическом обновлении. Поддерживай эти пояснения при изменении архитектуры проекта; не заявляй, что статический анализ подтверждает выполнение тестов.

Только когда пользователь запросил commit/push:

1. Если Git-репозиторий уже существует, подключи хуки командой `python project_map.py --install-hooks`. Существующие чужие хуки не заменяй; при их наличии подключи экспортёр к принятому в проекте процессу.
2. Перед commit обнови карту по staged-снимку: `python project_map.py --mode index`, затем включи только `.inkmap/project.json` в индекс командой `git add -- .inkmap/project.json`. Это также выполняет pre-commit hook.
3. Перед push проверь закоммиченный снимок: `python project_map.py --mode head --check`. Это также выполняет pre-push hook. При устаревшей карте сначала исправь её в следующем разрешённом пользователем commit; не используй amend, reset или force-push самостоятельно.

Не инициализируй Git и не создавай удалённый репозиторий только ради обновления карты без запроса пользователя.

В финальном отчёте укажи root cause, изменения, файлы, verification, build result и что осталось проверить вручную.
